# VelaCare ESP32-S3 传感器网关

网关固件用于连接 ESP32-S3、D12x VelaCare 与家庭 Wi-Fi。

## 当前行为

- 每秒发送一帧 `VC1` 心跳，波特率 115200、8N1。
- 漏水状态由雨水比较器模块的 `DO` 实时输入；烟雾状态由 MQ-2 比较器模块的 `DO` 经电平转换后实时输入；门磁由 GPIO6 实时输入；跌倒由 MPU-6500/MPU-9250 IMU 经 I²C 实时采样。
- v0.8.1 门磁：两线干接点接 GPIO6 和 GND，不分极性，不接电源、不需电平转换。GPIO6 使用内部上拉，持续稳定 80 ms 后确认；LOW 为正常，HIGH 为告警。磁铁靠近是否导通必须通过实物测试确认，若相反不要改接电源，应调整软件极性。
- 门磁首次确认前为离线。断线与开门均为 HIGH，当前两线接法无法区分；只适合本阶段短线桌面验证，不等同于具备线路监测的安防系统。
- 雨水输入为低电平告警：持续 0.8 秒确认湿润，持续 2.5 秒确认恢复，避免触点抖动。
- 烟雾输入为低电平告警：启动后预热 60 秒，持续 1 秒确认告警，持续 5 秒确认恢复。
- v0.11.0 跌倒检测：I²C 使用 GPIO8(SDA)/GPIO9(SCL)，默认地址 `0x68`；启动时读取 `WHO_AM_I` 识别 MPU-6500/MPU-9250。算法采用“失重候选 → 冲击 → 姿态变化 → 静止确认”的组合条件；组合条件确认后进入“严重告警”，持续 15 秒未恢复升级为“持续未恢复”。
- v0.10.0 报警分级：普通提醒（数字传感器刚触发）、严重告警（跌倒组合条件确认）、持续未恢复（跌倒持续 15 秒，其他传感器持续 30 秒）。分级会出现在状态接口、事件历史和网页卡片中。
- v0.10.0 断网缓存：事件记录始终写入独立 NVS，并保留 `syncPending` 标记。可在 `/configure` 设置可选 HTTP POST 接收地址；断网时先缓存，恢复网络后按时间顺序补传，服务端返回 2xx 后才标记为已补传。未配置地址时事件只保存在本机，不影响报警。
- v0.11.0 自检与报警控制：`/selftest` 显示 IMU 芯片、实时加速度/角速度、姿态阶段、数字输入电平和报警确认/静音状态；串口支持 `imu status`、`alarm ack`、`alarm mute`、`alarm unmute`。蜂鸣器为 D12X 板载器件，ESP32 不占用额外 GPIO。确认/静音只发 `VCB1`，只停蜂鸣器，不改写 `VC1` 传感器真值。
- v0.12.0 老人确认安全：D12X 跌倒后发送 `OK1,<id>*CRC`。网关记录 `elderConfirmed`，守护页显示「老人已确认安全」。该确认不把跌倒/门窗/烟雾/漏水改回正常；跌倒恢复后自动清除。
- v0.14.0 适老中文语音：ESP32-S3 通过 MAX98357A 和外接扬声器播放提示；语音在独立 FreeRTOS 音频任务中分块播放，不阻塞 IMU 采样、数字传感器检测、D12X 心跳和网页服务。D12X 只使用自己的板载蜂鸣器，不承担中文语音播放；音频失败也不会改变报警状态。
- v0.14.1 跌倒恢复根因修复：真实跌倒组合条件确认后立即结束当前采样处理，避免同一轮的冲击窗口超时逻辑把 `kFallAlarmed` 错误重置为监测态。告警确认后会持续进入真实姿态恢复判断，重新接近站立参考姿态并稳定 2.5 秒才恢复正常。
- v0.14.2 确认与蜂鸣可靠性：老人首次确认安全时立即使同次跌倒的旧询问/未回应语音失效，并把安全反馈语音插到队首；ESP32 每秒幂等同步一次 `VCB1` 蜂鸣控制状态，单帧偶发丢失后也能自动重新一致。两项操作均不改写传感器真值。
- v0.14.3 防突发同步：心跳和照护人配置同步采用“发送当前最新状态后重新计时”，ESP32 即使因网络或音频短时繁忙，也不会恢复后追赶式补发历史 UART 帧。
- VC1 帧中的 Wi-Fi 状态来自真实的 `WiFi.status()`，不能再用命令伪造在线。
- 连接家庭 Wi-Fi 后提供适配手机和桌面的产品化仪表盘，每秒刷新烟雾、漏水、门窗、跌倒、报警等级、待补传数量、在线数量、信号质量和网关运行状态，并提供确认/静音操作。
- D12x 通信 UART：ESP32-S3 `TX=GPIO17`、`RX=GPIO18`；IMU 中断预留 GPIO10，目前算法采用轮询采样。
- USB-UART 调试口会输出完全相同的发送帧。
- 每帧使用 CRC16/CCITT-FALSE，初值 `0xFFFF`、多项式 `0x1021`。

示例：

```text
VC1,1,1,1,1,1,0*XXXX
```

## 适老中文语音

语音只用于解释状态和安抚老人，不能代替传感器状态机。当前四段文案及触发条件如下：

| 触发条件 | 播放文案 |
| --- | --- |
| 跌倒状态首次由非告警进入告警 | 「检测到疑似跌倒，请问您还好吗？」 |
| 跌倒持续 15 秒仍未恢复且未收到回应 | 「暂未收到回应，正在通知家人。」 |
| 网关端首次确认当前报警 | 「家人已经收到消息，请不要着急。」 |
| 老人在 D12X 点击“确认安全”，网关首次收到有效 `OK1` | 「好的，已经向家人报告您目前安全。」 |

播放和取消规则：

- 同一状态边沿只入队一次，不会因为每秒心跳或网页刷新而反复播报。
- 真实 IMU 判断跌倒已经恢复，或调试时执行 `fall normal` 后，会取消尚未播放的本次跌倒提示和持续未恢复提示，避免恢复后再播过期消息。
- `alarm mute` 和网页“静音 10 分钟”会立即停止当前报警语音并清除待播放报警语音；静音期间不重复播放旧报警，取消静音也不会自动补播旧消息。
- `alarm ack` 和网页“确认并停止蜂鸣”会停止持续报警声，并仅播放一次“家人已经收到消息”；它表示家人已看到，不表示风险已经消失。
- 老人在 D12X 点击“确认安全”只产生关怀反馈和网页记录。若 IMU 姿态尚未满足恢复条件，跌倒卡片仍保持告警。
- 确认和静音不会修改 `sensorStates[]`，也不会伪造 `VC1`。门窗仍开、烟雾/漏水仍触发或跌倒尚未恢复时，D12X 和网关页面必须继续显示相应告警；只有真实传感器确认恢复，状态才会回到正常。
- 音频队列满、MAX98357A 未连接或播放失败时，只记录音频错误，不解除告警、不停止事件升级，也不影响事件缓存和上传。

## 首次 Wi-Fi 配置

没有已保存网络时，ESP32 会创建热点：

- 名称：`VelaCare-Setup-xxxx`，末尾四位因设备而异。
- 密码：仅保存在设备本地，公开仓库与报告中不写明文。
- 配置地址：`http://192.168.4.1`

用手机连接该热点，打开配置地址，填写家庭 Wi-Fi 名称和密码。配置只保存在 ESP32 本机 NVS，串口日志不会打印家庭 Wi-Fi 密码。连接成功后，D12x 的网络状态会由离线变为在线。

如果家庭 Wi-Fi 无法连接，15 秒后配置热点会自动启动。

连接成功后，临时配置热点会关闭。手机连接到与 ESP32 相同的家庭 Wi-Fi 或手机热点，然后访问串口输出的 IP 地址，例如：

```text
http://10.155.227.236/
```

状态页面为只读页面，不提供远程修改传感器状态或触发报警的入口。JSON 状态接口为 `/api/status`，Wi-Fi 配网页保留在 `/configure`。

## 告警历史与断网补传

- 告警状态变化会写入 ESP32 独立 NVS，断电后保留。
- 最多保留最近 12 条，记录设备类型、开始时间、持续时长以及进行中、已恢复或重启中断状态。
- 联网后通过 NTP 校准事件时间；尚未校时的事件使用本次启动运行时间标识。
- 告警历史接口为 `/api/events`，只读仪表盘最多展示最近 8 条。
- `/api/status` 增加 `alarmSeverity`（0 普通提醒、1 严重告警、2 持续未恢复）和 `pendingEvents` 字段；`/api/events` 增加 `severity`、`severityName`、`syncPending` 字段。
- `/api/diagnostics` 提供 IMU 和数字输入自检数据；`/selftest` 为可视化自检页面。报警控制接口为 `POST /api/alarm/ack`、`POST /api/alarm/mute`、`POST /api/alarm/unmute`。
- 在 `/configure` 的“事件补传”中填写接收端 URL（例如 `http://电脑IP:端口/api/events`）。接收端应接受 JSON POST 并返回 2xx；留空则关闭外部补传，但本地 NVS 缓存仍然有效。
- 持续时长使用 ESP32 单调运行时间计算，不受 NTP 校时跳变影响。

## 调试命令

通过 USB-UART 串口以 115200 波特率发送：

```text
status
normal
smoke alarm
smoke normal
water alarm
door alarm
fall alarm
fall normal
imu status
audio status
audio test
audio play fall
audio play persistent
audio play family
audio play elder
audio stop
alarm ack
alarm mute
alarm unmute
wifi status
wifi portal
wifi reconnect
wifi forget
```

状态值为 `offline=0`、`normal=1`、`alarm=2`。

漏水状态由 GPIO4、烟雾状态由 GPIO5、门磁状态由 GPIO6、跌倒状态由 I²C IMU 实物输入持续刷新；对应调试命令适合链路排查和复位。`fall normal` 可在安全测试后解除跌倒告警。

`audio status` 显示 I²S 是否就绪、MAX98357A 使用的 DIN/BCLK/LRC 引脚、采样率、播放状态、队列深度和播放统计。`audio test` 将三声连续升高的短提示音加入播放队列；`audio play fall|persistent|family|elder` 可逐句试听四段中文，`audio stop` 立即终止当前音频并清空队列。这些命令只验证 `ESP32-S3 → I²S → MAX98357A → 扬声器` 链路，不会制造跌倒告警，也不会修改任何传感器状态。执行测试前先确认扬声器已经接在 MAX98357A 的 `SPK+`、`SPK-`，避免功放空载或导线短路。

`wifi forget` 会清除 ESP32 中保存的家庭 Wi-Fi 名称和密码，并重新开启配置热点。

## 接线边界

当前 ESP32 与 D12x 的发送链路已经通过正常、报警、蜂鸣及恢复测试。

后续接线时只连接：

- ESP32-S3 `GPIO17/TX` → D12x `RX1`
- ESP32-S3 `GPIO18/RX` ← D12x `TX1`（首轮只发送时可暂不接）
- ESP32-S3 `GND` ↔ D12x `GND`

两块板分别使用各自 USB 供电，不连接两块板的 3V3 或 5V。双方 UART 都是 3.3 V，不使用 5 V 电平。

MAX98357A I²S 功放和扬声器接线：

- MAX98357A `VIN` → ESP32-S3 `5V`
- MAX98357A `GND` → ESP32-S3 `GND`
- MAX98357A `DIN` → ESP32-S3 `GPIO7`
- MAX98357A `BCLK` → ESP32-S3 `GPIO15`
- MAX98357A `LRC`（或 `LRCLK`、`WS`）→ ESP32-S3 `GPIO16`
- 扬声器两根线分别接 MAX98357A `SPK+`、`SPK-`

`SPK+`、`SPK-` 是桥接功放差分输出，扬声器任一端都不能接 GND、3V3 或 5V。单只扬声器的两根线对调通常只改变相位，不影响是否发声；固定接线后不要带电插拔或让两端短路。MAX98357A 的 `SD`、`GAIN` 保持模块默认状态即可。GPIO7、GPIO15、GPIO16 与现有 GPIO4 漏水、GPIO5 烟雾、GPIO6 门磁、GPIO8/9/10 IMU 和 GPIO17/18 D12X UART 不冲突。

雨水比较器模块使用 3.3 V 供电：

- 模块 `VCC` → ESP32-S3 `3V3`
- 模块 `GND` → ESP32-S3 `GND`
- 模块 `DO` → ESP32-S3 `GPIO4`
- 模块 `AO` 暂不连接
- 雨滴板连接模块的两针接口，不分正负

不要把雨水模块接到 5 V。

MQ-2 比较器模块和四路电平转换板接线：

- MQ-2 `VCC` → ESP32-S3 `5V`
- MQ-2 `GND` → ESP32-S3 `GND`
- MQ-2 `DO` → 电平转换板 `HV1`
- 电平转换板 `HV` → ESP32-S3 `5V`
- 电平转换板 `LV` → ESP32-S3 `3V3`
- 电平转换板两侧 `GND` → ESP32-S3 `GND`
- 电平转换板 `LV1` → ESP32-S3 `GPIO5`
- MQ-2 `AO` 暂不连接

MQ-2 金属探头工作时会发热。测试时保持通风，不要在面包板和导线附近使用打火机或明火。

MPU-6500/9250 惯性模块接线：

- 模块 `VCC` → ESP32-S3 `3V3`
- 模块 `GND` → ESP32-S3 `GND`
- 模块 `SDA` → ESP32-S3 `GPIO8`
- 模块 `SCL` → ESP32-S3 `GPIO9`
- 模块 `INT` → ESP32-S3 `GPIO10`（可选，当前算法轮询，不接也能工作）
- 模块 `AD0` → `GND`，使用地址 `0x68`
- `EDA`、`ECL`、`NCS`、`FSYNC` 暂不连接

先使用 3.3 V 供电，不要把模块的 I²C 上拉电平接成 5 V。该功能是桌面原型级的疑似跌倒识别，不替代医疗或认证安防设备。
