## 2、摘要

独居老人发现家里异常慢，家人又看不到现场。VelaCare 把老人端放在匠芯创 D12X 的 4.3 寸适老屏上，把烟雾、漏水、门窗和跌倒四路传感器放到 ESP32-S3 网关，经 UART 每秒上报 VC1 心跳。家人网页可以确认和静音，但静音只停蜂鸣器，不改写传感器真值；门还开着，界面就必须继续显示异常。跌倒用 2026-09-18 本机标定的双锚点姿态，回到安全姿态并稳定 2.5 秒才恢复。语音在 ESP32 播放，避免 D12X 本地 TTS 把界面卡死。当前可演示版本为 D12X v0.8.0 与 ESP32 v0.15.1。没有加载小米 MiMo，也没有运行时 ai_agent。跌倒是比赛原型，不是认证设备。

## 3、正文

### 3.1 绪论

#### 项目背景与问题定义

本作品面向独居老人和家庭照护者。老人要看的是“现在安不安全、出了事怎么告诉家人”；家人要看的是“老人那边到底怎样、我点了确认会不会把真警报盖掉”。常见痛点很具体：

1. 老人看不清小字、找不到开关，复杂菜单等于没有功能。
2. 门窗开着、疑似漏水、烟雾探头报警时，老人端和家人端说法不一致，家人以为处理好了，现场其实还在告警。
3. 跌倒最怕两头错：误报吵死人，真摔倒后又恢复不了，或者老人点了“我没事”就把告警清掉。
4. 断网以后事件丢了，家人回来什么也看不到。

所以产品边界先定死：先做看得见、说得清、恢复得对的居家安全终端，再谈以后的智能体。

#### 技术难点

1. 两块异构板要保持同一份传感器真值。D12X 跑 openvela/LVGL，ESP32 管 GPIO、IMU、Wi-Fi 和喇叭。
2. 静音、确认、老人“确认安全”都不能改写 VC1 里的烟雾/漏水/门窗/跌倒字段。
3. D12X 在 LVGL 线程做串口或本地 TTS 会卡死，这是真机踩过的坑。
4. 没有认证跌倒传感器，只能用 IMU 姿态做可复现的原型，并且把安全姿态和跌倒姿态分开标定。
5. 比赛材料必须交源码、真实 AI 日志和自建 Skill，不能只交镜像。

#### 创新点

1. 交互上把“告警是不是还在”和“声音开不开”拆开。家人静音不等于现场恢复。
2. 跌倒恢复看 IMU 是否回到安全锚点，不看老人有没有点按钮。老人确认只通知家人。
3. 语音放在 ESP32，D12X 只做大字界面和板载蜂鸣器，换来界面不卡。
4. 开发过程本身沉淀成 `skills/velacare-dev/`，把反复踩过的协议、烧录和提交约束写成可复用 Skill。

### 3.2 系统方案设计

#### 系统总体架构

```
烟雾 MQ-2 / 漏水探头 / 门磁 / IMU
                │
                ▼
     ESP32-S3 网关 v0.15.1
     ├── 采集与分级
     ├── 双锚点跌倒
     ├── 中文语音（MAX98357A）
     ├── 网页 /dashboard、/selftest
     └── 断网事件写入 NVS（最多 12 条）
                │ UART 115200 VC1/VCB1/FAM1/OK1
                ▼
     D12X-DEMO68-V1-2 + openvela
     ├── LVGL 480x272 适老四页
     ├── 板载蜂鸣器
     └── 老人确认安全、求助、家人页
```

数据流只有一条真值：传感器状态由 ESP32 产生，经 VC1 发给 D12X 显示。VCB1 只携带静音/确认/严重度，用来停蜂鸣器。OK1 只表示老人按了确认安全。

#### 方案论证与选型

| 方案 | 结论 |
| --- | --- |
| 全部做在 D12X | 屏和触控合适，但外接传感器、Wi-Fi 网页和喇叭不合适，本地 TTS 还卡死过 |
| 全部做在 ESP32 | 采集和联网方便，但没有 4.3 寸适老屏，不符合老人端 |
| D12X 老人端 + ESP32 网关 | 采用。图形留在 openvela，采集、语音、网页留在 ESP32 |
| 云端 MiMo 做主判断 | 不做。断网必须还能告警。当前固件没有加载 MiMo |

断网降级：本地 UART 和界面继续工作；网关把事件写入 NVS，最多 12 条，网络恢复后再补传。没有云端推理，因此弱网不会让核心告警停掉。

不是新硬件平台适配赛道，没有做全新 BSP。

#### 关键模块设计

1. 采集模块（ESP32）：门磁 GPIO6，漏水 GPIO4，烟雾 GPIO5，IMU I2C GPIO8/9，喇叭 I2S GPIO7/15/16。
2. 协议模块：CRC16/CCITT-FALSE，1 秒一帧 VC1，避免积压旧帧。
3. 协同模块：家人确认/静音走 VCB1；老人确认走 OK1；家人回复走 FAM1。
4. 交互模块：D12X 四页加大按钮；ESP32 提供家人网页。

### 3.3 核心算法与技术原理

#### AI 算法实现

当前交付固件没有在板端加载小米 MiMo，也没有运行 openvela `ai_agent`。没有端侧模型框架、量化和云端鉴权可写。AI 用在开发期：用 Codex 写固件、查卡死、标定跌倒、整理提交材料。这是开发工具，不是运行时推理。

#### 关键机制设计

1. 报警分级：普通提醒、严重告警、持续未恢复。跌倒默认按严重告警处理；长时间不回到安全姿态再升级。
2. 双锚点跌倒：安全姿态 (0.149537, 0.059815, 0.986945)，跌倒姿态 (-0.957276, -0.199432, 0.209404)，夹角约 87.04 度。靠近跌倒锚点触发，靠近安全锚点并稳定 2.5 秒恢复。不要用跌倒姿态覆盖安全锚点。
3. 真值与控制分离：VC1 是真值，VCB1 是蜂鸣器控制，OK1 是老人应答。
4. 断网缓存：最多 12 条，恢复后补传。

#### openvela 系统能力的深度运用

落地的是图形，不是板端 AI，也不是 D12X 多媒体播放。

用到的 openvela 能力：NuttX 应用框架、LVGL 480x272 界面、中文字体、触控、板载蜂鸣器 PWM、UART `/dev/ttyS1`、本地文件 `request-state.bin`。

对 openvela 的建议：在 LVGL 线程做阻塞串口或 PCM 播放很容易把界面卡死；比赛文档如果鼓励板端 Agent，最好同时给 D12X 这类 8MB PSRAM 板一个“开发期 Skill / 运行时 Skill”的明确区分，避免队伍为了得分去宣称没有真正跑起来的 ai_agent。

### 3.4 系统实现

#### 软件 / 固件架构

D12X 应用在 `app/velacare/`，通过 `contest2026_438_baimi.xml` 映射到 `packages/demos/contest2026_438_velacare`。主要文件：`velacare_main.c`、`velacare_sensor.c`、`velacare_lvgl.c`、`velacare_settings.c`、`velacare_state.c`、`velacare_buzzer.c`。`velacare_skill.c` 和 `velacare_cron.c` 仍是占位，链接进去只为保持构建，不代表运行时已加载 Skill。

ESP32 应用在 `gateway/esp32_velacare_gateway/`，版本常量 `kFirmwareVersion = "0.15.1"`，语音 PCM 在 `voice_prompts.h`。

#### 数据流与关键流程

1. ESP32 每秒组 VC1，D12X 刷新设备页。
2. 门磁断开：两端显示门窗异常，蜂鸣器按级别响。
3. 家人点确认/静音：发 VCB1，D12X 蜂鸣器停，门窗文案仍是异常。
4. IMU 到跌倒姿态：ESP32 播“检测到疑似跌倒”，D12X 出“确认安全”。
5. 老人点确认安全：发 OK1，网关显示老人已确认，跌倒字段不变。
6. 放回安全姿态并保持 2.5 秒：跌倒恢复，确认锁存清除。

#### 硬件设计与适配

是否完成全新硬件平台适配或驱动开发：否。使用官方板 `D12X-Demo68-nor`。

| 模块 | 接口 | 说明 |
| --- | --- | --- |
| 匠芯创 D12X-DEMO68-V1-2 | 4.3 寸 480x272、板载蜂鸣器、UART1 | 老人端 |
| ESP32-S3 | 8MB Flash | 网关 |
| 门磁 | GPIO6 / GND | 内部上拉，低电平正常 |
| 漏水比较器 | GPIO4 | 低电平告警 |
| MQ-2 烟雾比较器 | GPIO5 | 低电平告警，比赛原型 |
| MPU-6500/9250 | SDA GPIO8、SCL GPIO9，地址 0x68 | 不是 MPU6050 |
| MAX98357A + 喇叭 | DIN GPIO7、BCLK GPIO15、LRC GPIO16 | 语音只在 ESP32 |

#### 应用 / 交互端设计

老人端四页：首页、设备、求助、家人。跌倒时全屏大按钮“确认安全”。家人端是网关网页，不是手机 App。求助页用于联系家人，设置页用于查看连接和自检，不再放空功能。

#### 自定义 Skill

硬性要求的自建 Skill 是 `skills/velacare-dev/`。它记录本队真实反复使用的流程：Windows 工作文件和 WSL 继承单元怎么分、什么时候重建哪块 MCU、VC1/VCB1/OK1 不能混、双锚点跌倒、COM4/COM8 烧录规则、提交时不要交镜像和示例日志。

`data/agent/skills/` 下四份看护草稿（家庭安全、老人提醒、日常作息、紧急广播）是设计阶段写给以后 `ai_agent` 用的。当前 v0.8.0 固件不会读 `/data/agent/skills/`。赛道要求说明运行时 Skill 的触发场景：设计上希望按“家里安全吗 / 吃药了吗 / 紧急”来触发，但这些触发在当前固件里没有接上。不能把草稿写成已经在板子上执行。

### 3.5 系统测试与结果分析

#### 测试环境

- 真机：D12X-DEMO68-V1-2 + ESP32-S3，共地 UART，不并电源。
- 固件：D12X v0.8.0 family-care，ESP32 v0.15.1。
- 网络：手机热点配网，SSID 形如 VelaCare-Setup-xxxx。热点密码不写入仓库。
- 测试方式：台架手工复现，不是认证实验室，也没有大规模样本准确率。

#### 功能测试

| 测试项 | 结果 |
| --- | --- |
| 上电 3 秒内心跳 | 通过。D12X 不再显示离线 |
| 门磁开合 | 通过。打开显示异常，合上恢复 |
| 静音后门窗仍异常 | 通过。蜂鸣器停，界面不恢复 |
| 跌倒触发与语音 | 通过。ESP32 播报，D12X 出确认安全，界面不卡死 |
| 老人确认安全 | 通过。网关显示已确认，跌倒仍保持 |
| 回到安全姿态 2.5 秒 | 通过。跌倒恢复 |
| 只播语音不造跌倒 | 通过。`audio play fall` 不改 VC1 |
| 断网缓存 | 已实现 NVS 最多 12 条；本次提交以源码和台架流程为准 |

#### 性能测试

| 指标 | 数据 | 口径 |
| --- | --- | --- |
| UART 心跳 | 1 秒/帧 | 源码周期，台架可观察 |
| 跌倒恢复门限 | 2.5 秒 | 靠近安全锚点后计时 |
| 双锚点夹角 | 约 87.04 度 | 2026-09-18 本机标定 |
| D12X 分辨率 | 480x272 | 官方屏 |
| 端侧模型推理帧率 | 无 | 未加载端侧模型 |
| 功耗 | 未测 | 不填估计值冒充实测 |

#### 可靠性与稳定性

没有医疗级跌倒准确率、误报率、漏报率可报，不编造。兜底办法是：姿态必须靠近跌倒锚点才报；恢复必须靠近安全锚点并稳定 2.5 秒；老人确认不能自行消警。连续运行时长和内存曲线本次没有做 24 小时仪表记录。已经用真机修过的稳定性问题是：D12X 本地 TTS 导致跌倒后界面卡死，现已改为 ESP32 放音。

开发几乎全程对着真机进行：黑屏烧录、门磁、蜂鸣器静音、跌倒卡死、喇叭改接到 ESP32、双锚点标定。AI 日志按官方目录写在 `logs/gouzhongfei/`，是 Codex Desktop 导出的真实 jsonl，不是 example 占位。因为开发发生在 `C:\Users\gzf\Desktop\open-vela`，不在官方 `.repo` 工作区，比赛插件没有自动归集，所以改为手工导出并在 manifest 里说明。

遇到的问题和解决：

1. 把静音做成“界面恢复”会让门窗假恢复。后来改成 VCB1 只停蜂鸣器。
2. D12X 本地说话会卡死。后来喇叭改接 ESP32。
3. 跌倒恢复不稳定。后来记下安全姿态和跌倒姿态两个锚点。

### 3.7 总结与展望

#### 成果总结

做出了一个可演示的老人端加家人端闭环：四路原型传感器、适老界面、分级告警、静音不改真值、双锚点跌倒、ESP32 中文语音、断网缓存，以及自建开发 Skill 和真实 AI 日志。

#### 应用前景与商业价值

目标受众是独居或白天家中无人的老人，以及他们的子女。产品形态是家门口/床边的一块大屏，加上家人网页，不要求老人会用智能手机。商业上更接近适老化配件和社区看护试点，而不是替代认证烟感和医用跌倒报警器。规模化之前必须换成认证传感器，并补上真正的运行时 Agent。

#### 不足与未来工作

1. 没有板端 MiMo / `ai_agent`。
2. 跌倒、烟雾都是原型。
3. 演示视频计划 2026-09-19 补拍，当前仓库不放损坏或空白视频。
4. 作品照片还缺少完整的前/后/侧/俯产品照，将与视频一起补。
5. 未测功耗和长时间内存曲线。
